# AI Event & Venue Space Planner

โปรเจกต์วิชา **IT232 Artificial Intelligence for Information Technology** — *AI Transformation Project: AI to the Rescue*

บอกโจทย์ของงานเป็นภาษาธรรมดา (เช่น "งานสัมมนา 100 คน มีเวทีและซุ้มอาหาร งบ 5 หมื่นบาท") แล้วได้ผังพื้นที่ รายการอุปกรณ์พร้อมราคาโดยประมาณ ตารางเทียบ 3 ระดับงบ และคำแนะนำ

เวอร์ชันนี้เป็น **ไฟล์แบนทั้งหมด (ไม่มีโฟลเดอร์ย่อย)** เพื่ออัปโหลดขึ้น GitHub ผ่านหน้าเว็บได้

## ไฟล์ในโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | เว็บแอปไฟล์เดียว (GitHub Pages) มี CSS/JS/ข้อมูลในตัว ไม่ต้องติดตั้งอะไร |
| `app.py` | เว็บแอป Streamlit (`streamlit run app.py`) |
| `planner_engine.py` | rule engine: คำนวณพื้นที่ จำนวนอุปกรณ์ ราคา |
| `planner_parser.py` | ตัวอ่านโจทย์แบบ rule-based (ใช้เมื่อไม่มี AI) |
| `planner_ai.py` | เรียก Gemini/OpenAI อ่านโจทย์และเขียนคำแนะนำ มี fallback สลับโมเดลสำรอง ลองซ้ำเมื่อ 503/429 และปุ่มทดสอบการเชื่อมต่อ |
| `planner_floorplan.py` | วาดผังพื้นที่ (SVG) |
| `layouts.json`, `venue_rules.json`, `equipment.json`, `event_types.json`, `prompts.json` | ข้อมูลทั้งหมด แก้ได้โดยไม่แตะโค้ด |
| `DATA_SOURCES.md` | แหล่งที่มาของข้อมูลและระดับความน่าเชื่อถือ |
| `DEMO.md` | เช็กลิสต์และสคริปต์เดโม |

## วิธีรัน

- **เว็บ (GitHub Pages):** Settings -> Pages -> Deploy from a branch -> `main` / `(root)`
- **Streamlit:** Main file path = `app.py` ใส่ `GEMINI_API_KEY = "..."` ที่ Advanced settings -> Secrets (ไม่ใส่ key ก็ใช้ได้ด้วย rule-based) ห้ามใส่ key ลงในไฟล์ใน repo

## หลักการ

| ขั้นตอน | ทำโดย | เหตุผล |
|---|---|---|
| อ่านโจทย์ -> ข้อกำหนดแบบมีโครงสร้าง | LLM (few-shot prompt) หรือ rule-based เมื่อไม่มี key | ภาษาธรรมชาติคือจุดแข็งของ LLM |
| คำนวณพื้นที่ จำนวนอุปกรณ์ ราคา | rule engine จากไฟล์ `.json` | ตัวเลขต้องถูกต้องและตรวจย้อนกลับได้ ไม่ให้ AI เดา |
| เขียนคำแนะนำ | LLM จากตัวเลขที่คำนวณแล้วเท่านั้น | อธิบายเป็นภาษามนุษย์ |

ผลจาก LLM ผ่านตัวกรอง `sanitize_requirements` ทุกครั้ง ถ้าเรียก LLM ไม่ได้ระบบ fallback อัตโนมัติและแจ้งผู้ใช้พร้อมเหตุผลจริงจากผู้ให้บริการ

## แก้ปัญหาเมื่อเรียก AI ไม่สำเร็จ

กดปุ่ม **ทดสอบการเชื่อมต่อ AI** (เว็บ: ในกล่อง "ใช้ AI" / Streamlit: แถบด้านข้าง) ระบบจะตรวจ key รายการโมเดลที่บัญชีใช้ได้ และเรียกทดสอบ 1 ครั้ง แล้วแสดงเหตุผลจริงจาก Google

| ข้อความที่เห็น | ความหมาย | วิธีแก้ |
|---|---|---|
| `HTTP 400 INVALID_ARGUMENT API key not valid` | key ผิด วางไม่ครบ หรือมีอักขระแปลกปน | สร้าง key ใหม่ที่ Google AI Studio แล้ววางใหม่ทั้งหมด |
| `HTTP 403 PERMISSION_DENIED ...` | ฝั่ง Google จำกัดสิทธิ์ของโปรเจกต์/บัญชี (พบบ่อยกับบัญชีโรงเรียน/องค์กร) | สร้าง key จากบัญชี Gmail ส่วนตัวและยืนยันอายุ/เบอร์โทรในบัญชี Google |
| `ไม่พบโมเดล '...' ในบัญชีนี้ — ลองใช้: ...` | ชื่อโมเดลที่ตั้งไว้ใช้ไม่ได้กับบัญชีนี้ | ใส่ชื่อที่ระบบแนะนำในช่อง "ชื่อโมเดล" หรือเว้นว่างให้ระบบเลือกเอง |
| `HTTP 429` | โควตาฟรีหมดชั่วคราว | รอสักครู่แล้วลองใหม่ |
| `เชื่อมต่อไม่ได้` | ไม่มีอินเทอร์เน็ตหรือเครือข่ายบล็อก Google | ลองเครือข่ายอื่น |

ระหว่างที่ AI ใช้ไม่ได้ ระบบยังทำงานครบด้วยโหมด rule-based

## ข้อจำกัด

- ราคาอุปกรณ์เป็นค่าประมาณ (ดู `DATA_SOURCES.md`) ควรตรวจกับผู้ให้บริการจริง
- ผังพื้นที่เป็น schematic ไม่ใช่แบบก่อสร้าง ข้อมูลความปลอดภัยเป็นแนวทางเบื้องต้น ไม่แทนกฎหมายอาคาร
- ตัวอ่านโจทย์แบบ rule-based พลาดกับสำนวนที่ไม่มีคำสำคัญ (เช่น "meetup") โหมด LLM ช่วยในจุดนี้
